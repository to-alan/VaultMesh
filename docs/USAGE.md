# 首次使用：从登录到可恢复的备份

## 1. 保护管理员账号

用安装时给出的账号登录，立即修改初始密码，启用 TOTP 或域名下的通行密钥。恢复码放在独立密码管理器，不要只保存在这台控制面服务器。确认控制台通过可信 HTTPS 打开。

## 2. 创建存储仓库渠道

在存储仓库页面选择 S3 / R2 / SFTP / 其他实际使用的存储，填写专用路径、Restic 密码和最小权限凭据。先用独立测试 Bucket/Prefix，避免碰现有重要数据。

保存只代表配置格式有效，不保证存储可达。Restic 密码与存储凭据还应单独托管；控制面完全损坏时，也要能直接用 Restic 恢复。字段说明见[存储支持矩阵](STORAGE_PROVIDERS.md)。

## 3. 注册服务器并确认 Agent

在服务器页面生成注册命令，在相应源服务器安装 Agent。回到控制台确认在线、版本符合预期。一次令牌只注册一台主机；不要把 `state.json` 克隆到多台在线服务器。

## 4. 探测并建立项目

进入“备份项目”：宽屏左侧探测，右侧项目列表；小屏上下排列。选择服务器，再点击探测。选择服务器只读取上次报告，不会自动扫描或弹出项目编辑器。

- 推荐候选：进一步检查后可选，不是“已经备份”的标志。
- 需确认：已有项目涉及的路径、嵌套目录、配置或入口服务等，避免重复备份。
- 暂不可用：缺少工具、数据库不可达或不适合直接复制的数据库卷，先修复原因。
- 自动排除：VaultMesh 自身和 Agent 私有目录等，不生成业务项目；控制面另做专门灾备。

候选默认不勾选。勾选后生成草稿，核对服务器、来源绝对路径、仓库、计划、时区、保留策略，再保存。数据库用户名、密码、库名需要手工填写；探测不会读取密码。不要用普通 Docker 数据卷复制代替正在运行的数据库逻辑导出。

## 5. 完成第一轮验收

1. 先备份一个无敏感信息的小测试目录。
2. 点击立即备份，等待终态并查看运行明细；`partial` 不等于完全成功。
3. 到快照页面同步索引，确认能浏览文件。
4. 恢复到新的隔离目录，核对内容、哈希和权限；VaultMesh 不覆盖原生产路径。
5. 数据库再单独完成“逻辑导出 → 恢复到新数据库实例”的演练。
6. 配置计划和通知渠道，发送测试通知，并实际观察一次计划任务。

看到绿色成功只是起点；**真正能恢复**才是上线验收标准。按[恢复手册](SNAPSHOT_RECOVERY.md)继续检查。

## 6. 持续运行

定期看 Agent 心跳、失败/部分成功/迟到任务、快照更新时间、仓库 Check 和通知投递结果。先启用温和保留策略并预览，理解 Forget / Prune 的删除含义后再自动清理。永久保护标签不等于对象存储的 Object Lock。

控制面短时维护时 Agent 会继续按已保存计划运行，结果稍后补报。升级顺序始终是控制面/Web → Agent。控制面数据库和 `.env` 必须成对、异机加密备份；版本升级工具创建的本机备份不替代灾备。

完整策略见[备份项目](BACKUP_PROJECTS.md)、[通知与告警](NOTIFICATIONS.md)、[运维手册](OPERATIONS.md)。
