## 页面调整

- 总览提取为独立 OverviewView；先展示统计与项目风险，再展示运行样本和最近操作。空项目时提供接入服务器、配置仓库和创建项目的引导。
- 项目列表使用完整宽度；创建/编辑时打开独立宽表单，避免长表单长期挤占列表。返回列表保留草稿，放弃草稿返回列表，保存失败保留内容，保存期间锁定表单。
- 项目卡片突出编辑和立即备份，把维护策略、暂停及归档收纳到“策略与更多操作”。“运行中”筛选改为准确的“已启用”，风险筛选包含无效计划。
- 仓库页面去掉关于开发参考项目的大段说明，改为存储选择、服务器数据隔离和恢复密码说明。
- 同步失败不再继续显示“API 已连接”；通知页加载提示不再误写成审计事件。
- 调整桌面指标卡片布局、探测按钮宽度和手机 RPO 状态说明，保留表格内部滚动而不挤宽整页。

## 后续仍应单独处理

1. **命令排队状态与服务端事实绑定。** App 的手动备份/清理预览按钮仍使用固定 5/15 秒本地标记；下一轮应提供命令状态读取接口，按 command ID 跟踪领取、执行、完成和超时，避免跨页或刷新后状态丢失。
2. **暂停/恢复后的 RPO 基线。** 当前 ProjectHealth 从创建时间或最近成功时间推导应执行点，没有独立的恢复监控时间。需要明确恢复后首个计划的业务语义，并为暂停较久后恢复的场景增加持久化状态。
3. **运行、快照和审计分页。** 当前前端分别有固定数量上限；本轮已如实标注样本，不应把样本趋势当成完整历史。下一轮应增加游标分页及独立的时间范围统计接口。
4. **继续拆分 App 的异步状态。** 总览已拆出，但登录、项目编辑、探测和其他页面仍共享一个较大的组件及全局 loading。后续应拆分请求状态、加入请求过期保护，并完善批量快照同步部分成功时的反馈。
